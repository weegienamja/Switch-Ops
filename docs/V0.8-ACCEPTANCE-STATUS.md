## Defects corrected during acceptance

1. Invalid IOS command syntax previously became `UNSUPPORTED`. It now becomes
   command `UNAVAILABLE` and capability `UNKNOWN`; only an explicit
   feature-not-supported response yields `UNSUPPORTED`.
2. Authorization refusal, IOS execution error, transport loss, parser failure,
   unavailable syntax, explicit unsupported response, and successful empty
   output now remain distinct. Only explicit unsupported evidence can imply an
   unsupported capability.
3. A down access port now retains its observed administrative access mode.
4. Access ports no longer expose a meaningless trunk-native VLAN value.
5. Absence-based uplink findings now reference their CDP and LLDP evidence.
6. AAA absence is now represented with cautious, configuration-backed wording.
7. Inferred endpoint-facing interface failures now have bounded simulations
   without being promoted to physical uplinks.
8. Every Lab Assurance view now renders an explicit empty state, long content
   wraps safely, and narrow tab navigation remains horizontally bounded.

## Prepared multi-device procedure

The privacy-safe `scripts/v08-multidevice-acceptance.py` harness is ready for a
legitimate second IOS/IOS-XE instance. It does not accept or persist device
addresses, usernames, passwords, secrets, labels, interface descriptions, or
raw API state. It cannot create, delete, or fake a device. Onboarding, outage,
restoration, removal, and re-addition remain explicit operator actions through
the SwitchOps UI; the harness performs only the read-only refresh and evidence
checks.

Its checkpoints cover:

- Windows Credential Manager onboarding and API privacy;
- independent primary/secondary collection;
- one-sided and reciprocal discovery when actually present;
- physical, inferred L2, and logical routing edge semantics;
- failure isolation with retained current primary evidence;
- UI removal, new-ID re-addition, and recovery;
- VRF, EtherChannel, OSPF/EIGRP/BGP adjacency, BFD, EVPN, VXLAN/NVE,
  Segment Routing MPLS, and SRv6 as `PASS`, `FAIL`, `NOT CONFIGURED`,
  `NOT SUPPORTED`, or `NOT EXERCISED` according to emitted evidence.

A legitimately licensed virtual IOS/IOS-XE instance can close the platform and
multi-device behavior gate. It must be recorded as `licensed-virtual` and does
not close physical-hardware acceptance.
